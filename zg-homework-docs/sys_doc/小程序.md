## 1. 已确认的技术决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 技术选型 | **原生小程序**（WXML/WXSS/JS，无构建链） | 脚手架已是原生模板且 appid 已注册；体积最小、启动最快；无 node_modules 与构建步骤，调试链路最短 |
| 登录方式 | **沿用用户名 + 密码**，**一期不做微信一键登录** | 服务端零改动；四角色注册码逻辑（老师邀请码 / 班级邀请码 / 学生绑定码）与 Web 端完全一致；小程序审核允许非微信授权登录 |
| 功能范围 | **一期：学生端 + 家长端** | 覆盖家庭最高频场景（家长绑定孩子是全链路入口），可独立上线验证。**老师端与 admin 端确定要进小程序，但排在二期**（见 §1.1、§9） |
| 生产域名 | **与 Web 端共用同一域名** | 只需备案一个域名、一张证书、一次微信合法域名配置；详见 §2.5 |
| 仓库归属 | **仓外独立仓库** | 小程序是独立发布单元，构建与审核节奏不同 |

### 2.4 本机联调（开发期）

**结论：开发联调阶段全部走本机 `http://127.0.0.1:8000/homework_api`，不走 HTTPS 域名。**

需要满足三个条件，缺一不可：

| 条件 | 现状 | 说明 |
|---|---|---|
| 开发者工具「不校验合法域名」 | ✅ 已开启 | `project.private.config.json` 中 `urlCheck: false`、`useStaticServer: false`。**已在脚手架里配好，无需改动** |
| 服务端监听本机 | 需确认 | 检查监听 `127.0.0.1:8000`；`POST /homework_api/health` 应返回 `code:0` 和 `data.status: "ok"` |
| base URL 带 `/homework_api` | 规划中 | 见下 |

#### `localhost` vs `127.0.0.1`：一个实测的坑

本机 `localhost` **优先解析为 IPv6 `::1`**（实测 `getaddrinfo` 返回 `::1` 在前），
而 uvicorn 默认只监听 IPv4 `127.0.0.1`：

```
$ lsof -nP -iTCP:8000 -sTCP:LISTEN
python3.1 60414 zg 3u  IPv4  TCP 127.0.0.1:8000 (LISTEN)     # 只有 IPv4
```

实测结果：

| 访问方式 | 结果 |
|---|---|
| `curl -4 -X POST http://localhost:8000/homework_api/health` | ✅ `{"code":0,...}` |
| `curl -6 -X POST http://localhost:8000/homework_api/health` | ❌ 无响应（`::1` 未监听） |
| `curl -X POST http://localhost:8000/homework_api/health` | ✅ 通过（客户端有 IPv4 回退） |
| Node `http.request({host:'localhost'})` | ✅ 200（Node 默认 `autoSelectFamily` 会回退 IPv4） |

小程序 `wx.request` 的网络栈由微信开发者工具提供，**其 IPv6→IPv4 回退行为不受
小程序代码控制**。为消除不确定性，开发期 base URL **统一写 `http://127.0.0.1:8000/homework_api`**，
不用 `localhost`——IPv4 直连，不依赖任何回退逻辑。

> 若坚持用 `localhost`，必须把服务端改成监听 IPv6 或双栈：
> `uvicorn app.main:app --host ::`（或 `--host 0.0.0.0`）。当前 `scripts/dev.sh`
> 用的是 `--host 127.0.0.1`（仅 IPv4），故不建议。

#### base URL 配置方式

`utils/config.js` 集中管理，开发/生产通过**常量切换**（原生小程序无构建期环境变量，
这是与 Web 端 `import.meta.env` 的关键差异）：

```js
// utils/config.js
const DEV = true   // ← 提审前改为 false

// 开发态：直连后端，保留服务端真实前缀
const DEV_BASE_URL = 'http://127.0.0.1:8000/homework_api'
// 生产态：走 nginx 反代，保留前缀（见 §2.5）
const PROD_BASE_URL = 'https://<正式域名>/homework_api'

const API_BASE_URL = DEV ? DEV_BASE_URL : PROD_BASE_URL
const FILE_BASE_URL = API_BASE_URL   // /uploads 静态挂载同源
```

切换只需改 `DEV` 一个布尔值，**不引入任何构建步骤**（保持「无构建链」决策）。
`project.private.config.json` 是开发者私有配置（不进版本库），「不校验合法域名」
这一项已配好。

#### 真机调试的额外限制（重要）

开发者工具模拟器里 `127.0.0.1` 指本机，**真机预览 / 真机调试时 `127.0.0.1` 指的是手机自己**，
会连不上。此时需：

1. 服务端改为监听局域网：`uvicorn app.main:app --host 0.0.0.0 --port 8000`
   （当前 `scripts/dev.sh` 用的是 `--host 127.0.0.1`，**真机调试时需手动改**）
2. base URL 改为本机局域网 IP：实测本机为 `http://192.168.8.178:8000/homework_api`
   （IP 会随网络变化，每次调试前用 `ipconfig getifaddr en0` 确认）
3. 手机与电脑需在同一 WiFi

建议 `utils/config.js` 预留第三个常量便于切换：

```js
const DEV_BASE_URL = 'http://127.0.0.1:8000/homework_api'      // 开发者工具模拟器
const LAN_BASE_URL = 'http://192.168.8.178:8000/homework_api'   // 真机调试，IP 需按实际填写
```

### 2.5 生产环境：与 Web 端共用域名（已决策）

**决策：生产环境小程序与 Web 端共用同一个域名**，Web 端走 `https://<域名>/homework_api`，
小程序走 `https://<域名>/homework_api`。理由：

- 只需备案一个域名、申请一张证书、配置一次微信合法域名
- 微信合法域名有数量限制（主域名 + 每月修改次数），共用省资源
- `/uploads` 静态文件同源，PDF 导出/作业附件下载路径一致

#### 路径隔离与反向代理

服务端业务路由、健康检查和静态文件均以 `/homework_api` 为真实前缀；Web SPA 页面路由如 `/admin/users`、`/parent/*` 不带此前缀。nginx 按前缀区分请求，避免页面路由冲突：

```nginx
location /homework_api/ {
    proxy_pass http://server:8000;  # 不带 URI，原样保留 /homework_api/ 前缀
}
```

例如 `POST /homework_api/auth/login` 和 `GET /homework_api/uploads/x.pdf` 转发到服务端时路径不变。`proxy_pass` 若写成 `http://server:8000/`（带尾斜杠 URI），会替换匹配的 location 前缀，导致服务端路径不匹配。裸机部署时上游可用实际地址，如 `127.0.0.1:8000`。SPA 路由走 `location /` 和 `try_files ... /index.html`。

#### 配套配置

1. Web 生产配置为 `VITE_API_BASE_URL=/homework_api`；Vite 开发代理和 nginx 均保留前缀。
2. 小程序开发与生产的 API_BASE_URL / FILE_BASE_URL 均需包含 `/homework_api`。例如 `fileUrl('/uploads/x.pdf')` 拼成 `/homework_api/uploads/x.pdf`；文件访问的鉴权要求另见 §12。
3. 微信 `request`、`uploadFile`、`downloadFile` 合法域名填写 `https://<域名>`，不带路径；`/homework_api` 是请求路径的一部分。

#### 遗留问题（不在小程序范围，但共用域名会放大它）

- nginx 的 `proxy_pass http://server:8000` 依赖 Docker 网络里的 `server` 主机名，
  而仓库里**没有 docker-compose.yml**（已知缺陷 7）。生产部署需补 compose
  或改为写死的实际地址/IP。
- nginx 现有 `listen 80` 无 TLS。共用域名要求 HTTPS，需在 nginx 前置 443 + 证书，
  或改用云负载均衡卸载 TLS。**这是小程序上线的硬前提**，与 Web 端共用同一套证书。

## 4. 架构设计

### 4.1 网络层 `utils/request.js`

对标 Web 端 `zg-homework-web/src/api/client.ts`，保持语义一致：

```js
// 伪代码
const { API_BASE_URL } = require('./config')
const CODE = { OK: 0, BAD_REQUEST: 400, UNAUTHORIZED: 401, FORBIDDEN: 403, NOT_FOUND: 404, RATE_LIMIT: 429, SERVER_ERROR: 500 }

function post(path, body = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: `${API_BASE_URL}${path}`,   // API_BASE_URL 已含 /homework_api；path 相对 base
      method: 'POST',
      data: body,
      timeout: 15000,                  // 与 Web 端 axios timeout 一致
      header: {
        'Content-Type': 'application/json',
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
      },
      success(res) {
        const payload = res.data
        if (payload && payload.code === CODE.OK) resolve(payload.data)
        else reject(Object.assign(new Error(payload?.message || '请求失败'), { code: payload?.code }))
      },
      fail() { reject(new ServiceUnavailableError('服务端不可用')) },  // 对标 Web 的网络错误
    })
  })
}
```

约定（与 Web 端完全一致）：

- **全 POST + JSON Body**，参数不进 URL（PRD 3.1）
- 成功返回 `data` 字段；业务错误以 `{code, message}` 抛出，`err.code` 可用于分支
- 网络失败 / 超时统一抛 `ServiceUnavailableError`，由调用方降级展示，**不使应用崩溃**
- `wx.request` 默认超时 60s，显式设 15s 与 Web 端对齐

### 4.2 角色分流：为什么不用官方 tabBar

官方 tabBar 的页面列表在 `app.json` 静态声明，**无法按登录角色增减 tab 项**
（`wx.setTabBarItem` 只能改文案/图标，改不了数量）。

学生端 tab：首页 / 作业 / 阅读 / 游戏 / 我的（5 项）
家长端 tab：孩子 / 我的（2 项）

两者语义完全不同，无法共用一套静态 tabBar。

**方案：自绘底部导航 + 单容器页 + 组件内切换**（即「多个子页并存于同一容器、
切换时各自保留状态」的思路）：

```
pages/launch ──→ 按 role 决定目标页
                   student → packageStudent/pages/home/home
                   parent  → packageParent/pages/children/children
```

每个「首页」是**一个页面**，内部用 `<student-home-nav>` 等组件切换 5 个 Tab，
各 Tab 内容拆成独立组件：

```
home.wxml
├── <nav-bar tabs="{{tabs}}" current="{{current}}" bind:change="onTab"/>
├── <view wx:if="{{current === 'home'}}">   <student-home-panel/>  </view>
├── <view wx:if="{{current === 'homework'}}"><student-homework-panel/> </view>
├── <view wx:if="{{current === 'reading'}}"><student-reading-panel/> </view>
├── <view wx:if="{{current === 'games'}}">  <student-games-panel/>  </view>
└── <view wx:if="{{current === 'profile'}}"><student-profile-panel/> </view>
```

- 切 Tab 不产生新页面 → **不占页面栈**，天然规避 10 层限制
- `wx:if` 而非 `wx:for` + 复用，保证各 Tab 状态（滚动位置、已填内容）不丢
- 详情页（作业详情、阅读详情、积分明细、排行榜）用 `wx.navigateTo`，
  返回后底层 Tab 状态原样保留
- tab 数据与图标由 `app.js` 在登录后按角色注入 `globalData.roleTabs`

**代价**：首页单页内容较多 → 必须把每个 Tab 拆成独立组件，不能都写在 home 页里。

### 4.3 登录态管理 `utils/auth.js`

对标 Web 端 `store/auth.ts`：

| 行为 | 实现 |
|---|---|
| 存储 | `wx.setStorageSync('token')` / `wx.setStorageSync('user')`（JSON 字符串） |
| 恢复 | `app.js` 的 `onLaunch` 调 `POST /auth/me` 探测；**失败即清本地登录信息**（含网络故障），与 Web 端 `init()` 行为一致 |
| 运行期过期 | `request.js` 收到 `code === 401` → 清除本地存储 + `wx.reLaunch` 到登录页。**这是对 Web 端的改进**：Web 端无 401 全局拦截（已知缺陷 4），小程序端补上 |
| 强制改密 | 登录返回 `must_change_password: true` → 跳 `pages/change-password`，改密成功前不允许进入业务页 |
| 禁用账号 | 服务端每次请求回库校验，禁用后立即 403 → 提示并登出 |

### 4.4 启动流程

```
app.onLaunch
  └── 读本地 token/user
        ├── 无 token → reLaunch(pages/login)
        └── 有 token → POST /auth/me
              ├── 成功 → 按 role 分流到对应首页
              │           └── must_change_password → reLaunch(pages/change-password)
              └── 失败 → 清除本地 → reLaunch(pages/login)
```

`pages/launch` 作为 `app.json` 的第一个页面，仅承担跳转与加载态。

## 7. 关键技术难点与对策

### 7.1 作业附件上传（multipart）

服务端 `POST /homework/submit` 是 `multipart/form-data`（字段 `homework_id`、
`text_content`、`file`）。小程序无 `FormData`，用 `wx.uploadFile`：

```js
wx.uploadFile({
  url: `${API_BASE_URL}/homework/submit`,
  filePath: tmpFilePath,          // wx.chooseMessageFile / wx.chooseMedia 得到的临时路径
  name: 'file',
  formData: { homework_id: String(id), text_content: text },
  header: { Authorization: `Bearer ${token}` },
  success(res) {
    const body = JSON.parse(res.data)   // 注意：uploadFile 的 res.data 是字符串
    if (body.code !== 0) reject(...)
  }
})
```

要点：

1. `wx.uploadFile` 的 `res.data` **是字符串，必须 `JSON.parse`**，与 `wx.request` 不同
2. 临时文件在 `wx.chooseMessageFile` / `wx.chooseMedia` 回调里获取；选完立即上传，
   不做长期缓存（小程序本地文件会过期）
3. `file` 与 `text_content` **至少要有一个**，否则服务端返回 400
4. 服务端有 10MB 上限（`settings.max_upload_mb`）

**已下线 Flutter 端的教训**：该端的 `submitHomework` 曾收了 `filePath` 却没附加到请求。
小程序端实现时**必须**真正把文件挂上去，并做「有附件」的验收用例。

### 7.2 导出 PDF 的下载与预览

Web 端是 `window.open(fileUrl(...))`，小程序**没有浏览器环境**：

```
POST /articles/export-pdf  →  { file_url: "/uploads/xxx.pdf", file_name, size_bytes }
  ↓
wx.downloadFile({ url: FILE_BASE_URL + file_url })  → tempFilePath
  ↓
wx.openDocument({ filePath: tempFilePath, fileType: 'pdf', showMenu: true })
```

- `FILE_BASE_URL` 与 `API_BASE_URL` 同源（服务端 `/uploads` 静态挂载），本机联调时同为 `http://127.0.0.1:8000/homework_api`
- 开发期「不校验合法域名」已覆盖 `downloadFile`；**上线前 `downloadFile` 需单独配置合法域名**（与 request 分开配）
- `openDocument` 的 `fileType` 必须是 `pdf`，传错会失败
- 失败降级：提示「导出失败，请稍后重试」，不崩溃

### 7.3 阅读心跳计时（防挂机）

服务端校验：单次心跳 `seconds` 必须 ≤ `HEARTBEAT_INTERVAL(30) + HEARTBEAT_TOLERANCE(10) = 40`，
超出则**本次不计分**但仍记录。

小程序侧实现（对标 Web 的 `visibilitychange` 方案，小程序用 `onHide`/`onShow`）：

```js
Page({
  onLoad() { this.timer = setInterval(() => this.beat(), 30000) },
  onHide() { clearInterval(this.timer); this.timer = null; this.active = false },  // 切后台：停止上报
  onShow() { this.active = true; this.beat() },                                 // 回前台：恢复上报
  onUnload() { clearInterval(this.timer) },
  beat() {
    if (!this.active) return
    post('/articles/heartbeat', { article_id: this.data.id, seconds: 30 })
      .catch(() => {})   // 网络异常静默，等下次心跳；不打断阅读
  }
})
```

关键点：

1. `seconds` **固定传 30**（心跳间隔就是 30s），不要传本地累计时长
2. `onHide` 时**必须停掉定时器**——否则后台仍上报，用户被误判为挂机
3. `onShow` 恢复时**重新起定时器**，且首跳延后 30s（不能立刻打，否则两次心跳间隔过短）
   —— 注意：过短不会扣分（服务端只校验上限，不校验下限），但会稀释计分节奏
4. 本地秒表仅用于**展示**「已阅读 mm:ss」，不参与计分
5. 文章被下架（404 / `code === 404`）→ 停止计时并提示

**待确认的服务端细节**：服务端只校验上限不校验下限，因此心跳「快于 30s」不会被拒。
小程序端按 30s 固定节奏即可，无需额外处理。

### 7.4 成语会话只存在于服务端内存

`POST /games/idiom/start` 返回的 `session_id` 对应的会话在
`app/routers/games.py` 的 `SessionStore`（`threading.Lock` + 内存），
**不落库**。服务端多进程部署或重启 → 会话丢失，后续 `question`/`answer` 返回 404。

小程序端对策：

- 前端不做会话持久化（持久化了也没用，服务端已丢）
- 捕获 404「会话不存在或已过期」→ 提示「重新开始一局」并回到成语首页
- **部署约束**：小程序上线期间后端应单进程运行，或后续把成语会话改落库
  （此项属服务端改造，列入 §10 待办，不在本次小程序范围内）

### 7.5 数独 9×9 盘面

- 布局用 flex + `calc()` 或 grid，**小屏下 9 列等宽**；3×3 宫边界线用外层 `border` 叠加实现
- 提示数（服务端返回的非 0 初始值）不可改，选中格子高亮
- 数字键盘 1–9 + 清除，「提交答案」把 `board` 数组传给服务端复核
- 服务端会**复核答案**并返回 `success` 与 `points`，前端不自行判定对错
- 每日游戏合计 20 分上限（数独 + 成语共用），页面需展示该提示

### 7.6 页面栈深度

10 层限制的规避依赖 §4.2 的「Tab 切换不产生页面」设计。需额外注意：

- 从 Tab 进入详情 → 再进详情 → 返回，链路不超过 3 层，安全
- 详情页的二级弹层（批改、消耗）用**组件内 popup** 而非新页面
- 积分明细、排行榜用独立页面但都从 Tab 层进入，深度可控

### 7.7 微信登录态与业务登录态是两回事

**决策：一期不做微信一键登录**（§1）。小程序 `wx.login` 拿到的 code 一期**完全不使用**，
`wx.getUserProfile`（头像昵称授权）同样不用。

落地要求：

1. **移除脚手架 `app.js` 里那段 `wx.login` 演示代码**（`onLaunch` 中的
   `wx.login({success: ...})` 与「发送 res.code 到后台换取 openId」注释），
   避免后续维护者误以为要接微信登录
2. `globalData.userInfo` 脚手架遗留字段一并清理；改用 `globalData.roleTabs`
   承载角色 tab 配置（§4.2）
3. 账号体系仍以服务端的 `users` 表为准，**`users` 表不需要加 openid 字段**

#### 为什么一期不做，以及代价

| 方面 | 说明 |
|---|---|
| 收益（暂缓的） | 省一次「手机号 + 微信」双账号绑定流程；家长/学生不用记密码 |
| 代价 | 用户每次要输手机号 + 密码；家长绑定孩子时需要手输孩子的绑定码，多一次输入 |
| 服务端成本 | 微信登录需 `users` 表加 `openid` 唯一索引、新增 `/auth/wechat/login` 端点、<br>配置 appid/secret、换 session_key，且**与现有 JWT 签发逻辑要打通**——是一次实打实的服务端改造，不是纯前端改动 |
| 审核影响 | 微信审核**允许**非微信授权登录（只要不强制索取用户信息），故一期不构成阻塞 |

> 若二期决定补做，需要服务端改造（加 openid 字段 + 新端点 + 账号绑定/合并策略，
> 处理「已有账号如何与微信身份关联」的问题）。届时小程序侧需接 `wx.login` →
> code 换 session → 后端签发 JWT。**建议作为独立任务立项，不要塞进二期 M6/M7。**

### 7.8 小程序请求的额外限制

- 单个请求包体上限 1MB（普通）/ 2MB（上传）；作业附件走 `uploadFile` 不受此限
- 并发请求上限 10，超出排队；批量拉取时用 `Promise.all` 需控制数量（PRD 10.3 性能要求）
- `wx.request` 在 App 切后台时会中断；阅读心跳已由 §7.3 的 `onHide` 处理

## 12. 补充需求：家长作业、文章与鉴权文件访问

本节补充一期范围，以 PRD 第 14 节为准；与前文冲突时以本节为准。新增能力需要服务端实现并联调，前文「服务端零改动」「所有端点已存在」及公开链接下载方案不适用于本补充需求。

- 家长在孩子列表选择已绑定孩子，查看其当前班级作业列表、详情、提交与批改情况；无班级时显示空态。服务端每次校验绑定关系和当前班级，不能访问未绑定孩子或转出班级的作业。
- 家长可拍照并代孩子正式提交作业，使用 multipart 真正上传附件；提交规则、截止时间、迟交、重复提交、积分与批改沿用学生作业规则。不得伪造或代填开始时间：保留已有真实 `start_time`，未开始则为空，也不虚构用时。
- 家长只读查看已发布文章及其 PDF，不调用阅读心跳或读完接口，不为孩子产生阅读计时、阅读记录或积分；下架文章不可访问。

新增接口调用面（均为 POST，带 `Authorization: Bearer <token>`，字段放 Body）

```
/parent/homework/list      {student_id, page?, size?}
/parent/homework/detail    {student_id, homework_id}
/parent/homework/submit    multipart: student_id, homework_id, text_content?, file?
/parent/homework/download  {student_id, homework_id}   # 孩子作业附件
/homework/attachment       {homework_id, student_id?}  # 按角色和作业记录权限鉴权
/parent/articles/list      {page?, size?}             # 仅已发布
/parent/articles/detail    {article_id}                # 仅已发布
/parent/articles/download  {article_id}                # 仅已发布，PDF
```

- PDF 与附件下载必须使用上述带 Bearer 的 POST 接口，成功响应是二进制流而非统一 JSON；小程序可用 `wx.request` 的 `responseType: 'arraybuffer'` 接收，写入本地临时文件后用 `wx.openDocument` 等方式打开。错误响应按状态及内容类型识别并提示，不能把错误 JSON 当文件；不要用前文基于公开 URL 的 `wx.downloadFile` 方案替代。
- **历史风险**：服务端现存 `GET /homework_api/uploads/<name>` 静态挂载不鉴权，历史公开链接仍可能被持有者访问。新接口不自动撤销历史链接或保护存量文件，需另行治理。

**补充验收**

- [ ] 已绑定、未绑定、解绑、转班及无班级场景均正确隔离；家长只能访问孩子当前班级作业。
- [ ] 家长代拍附件真实上传并正式提交；重复提交、迟交、积分和批改与学生规则一致，不伪造开始时间及用时。
- [ ] 家长只能查看及下载已发布文章；访问不产生心跳、读完、阅读计时或积分。
- [ ] 附件及 PDF 使用 Bearer 鉴权 POST 二进制流打开；未认证、越权及下架资源被拒，历史公开链接风险已记录。
