下面给出 **zg-homework 单个项目的完整部署方案**，涵盖后端（FastAPI，端口 8001）、前端（Vite 构建静态文件）、Nginx 配置和 systemd 守护。
前端构建产物最终放到 `/data/apps/zg-homework-web/dist/`。
后端代码放到 `/data/apps/zg-homework-server/`。

server_package.sh / web_package.sh 已存在并有契约测试 
---

## 一、目录规划

```
/data/apps/
├── zg-homework-server/          # 后端代码（已存在）
│   ├── app/
│   ├── requirements.txt
│   └── venv/                    # 虚拟环境（稍后创建）
└── zg-homework-web/             # 前端代码/产物
    ├── src/
    ├── package.json
    └── dist/                    # vite build 产物
```

Nginx 直接读取 `/data/apps/zg-homework-web/dist/` 作为静态根目录。

---

## 二、后端部署（FastAPI，端口 8001）

### 1. 创建虚拟环境并安装依赖

```bash
cd /data/apps/zg-homework-server

# 用 Python 3.12 创建虚拟环境
python3.12 -m venv venv

# 安装依赖（建议 requirements.txt 锁定版本）
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r requirements.txt
```

### 2. 配置文件 `/etc/zg-homework-server/env`

```bash
sudo mkdir -p /etc/zg-homework-server
sudo tee /etc/zg-homework-server/env > /dev/null <<'EOF'
DATABASE_URL=mysql+asyncmy://zg_hw_user:密码@127.0.0.1:3306/zg_homework_db?charset=utf8mb4
SECRET_KEY=用 openssl rand -hex 32 生成
ACCESS_TOKEN_EXPIRE_MINUTES=30
EOF

sudo chown root:www-data /etc/zg-homework-server/env
sudo chmod 640 /etc/zg-homework-server/env
```

生成密钥：`openssl rand -hex 32`。

### 3. systemd 服务 `/etc/systemd/system/zg-homework-server.service`

```ini
[Unit]
Description=zg-homework FastAPI Server
After=network.target mysql.service

[Service]
User=www-data
Group=www-data
WorkingDirectory=/data/apps/zg-homework-server
EnvironmentFile=/etc/zg-homework-server/env
ExecStart=/data/apps/zg-homework-server/venv/bin/gunicorn \
    -k uvicorn.workers.UvicornWorker \
    -w 2 \
    --bind 127.0.0.1:8001 \
    app.main:app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

> `app.main:app` 需与你的 FastAPI 入口模块路径一致，若入口是 `main.py` 在项目根目录，则改为 `main:app`。

### 4. 启动并验证

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zg-homework-server
sudo systemctl status zg-homework-server

# 直连后端验证（应返回 401 或 200，而非连接拒绝）
curl -i http://127.0.0.1:8001/homework_api/health
```

确保 `/data/apps/zg-homework-server` 目录对 `www-data` 可读：

```bash
sudo chown -R www-data:www-data /data/apps/zg-homework-server
```

## 三、前端打包与部署（zg-homework-web）

### 1. Vite 配置

`vite.config.ts`：

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  base: '/homework/',   // 与 Nginx location 一致
  plugins: [react()],
  server: { port: 5173 },
})
```

### 2. React Router basename

```tsx
<BrowserRouter basename="/homework">
```

（或 `createBrowserRouter(routes, { basename: '/homework' })`，注意不带末尾斜杠。）

### 3. 前端 API 请求前缀

Axios 实例或 fetch 封装中，baseURL 设为 `/homework_api`：

```ts
const api = axios.create({ baseURL: '/homework_api' })
// 请求 /login → 实际发往 xxx.com/homework_api/login
```

### 4. 构建并放置产物

```bash
cd /data/apps/zg-homework-web
npm ci
npm run build          # 生成 dist/

# 确保 Nginx 可读
sudo chown -R www-data:www-data /data/apps/zg-homework-web/dist
```

产物目录结构应为 `dist/index.html`、`dist/assets/...`。**不需要**把 `dist` 内容再套一层 `homework` 子目录，因为 Nginx 用 `alias` + `try_files` 处理前缀。

---

## 四、Nginx 配置

编辑 `/etc/nginx/sites-available/zg-homework.conf`：

```nginx
server {
    listen 80;
    server_name xxx.com;   # 替换为你的域名

    # ---------- 前端静态文件 ----------
    location /homework/ {
        alias /data/apps/zg-homework-web/dist/;
        try_files $uri $uri/ /homework/index.html;
    }

    # ---------- 后端接口 ----------
    location /homework_api/ {
        proxy_pass http://127.0.0.1:8001;   # 不加末尾斜杠，路径原样透传
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Authorization $http_authorization;
    }
}
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/zg-homework.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

**`alias` 末尾斜杠**：`alias /data/apps/zg-homework-web/dist/;` 必须以 `/` 结尾，否则拼接路径会出错。`try_files` 的回退路径 `/homework/index.html` 是 URI 而非文件路径，由 Nginx 内部重新匹配 `location /homework/` 后从 `dist/index.html` 返回。

## 五、验证清单

```bash
# 1. 后端存活
sudo systemctl status zg-homework-server
curl -i http://127.0.0.1:8001/homework_api/health       # 401 属正常（未登录）

# 2. 前端静态文件
curl -I http://xxx.com/homework/                     # 200, text/html
curl -I http://xxx.com/homework/assets/xxx.js        # 200（用实际产物文件名）

# 3. 接口经 Nginx 转发
curl -i http://xxx.com/homework_api/health               # 401，说明转发成功
curl -X POST http://xxx.com/homework_api/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=test&password=xxx"

# 4. 浏览器验证
# 访问 http://xxx.com/homework/ → 页面正常
# 登录 → Network 中 /homework_api/login 返回 token
# 刷新 http://xxx.com/homework/some-route → 不 404（try_files 生效）
```

**常见故障对照**：

| 现象 | 原因 |
|------|------|
| `/homework/` 返回 403/404 | `alias` 末尾缺 `/`，或 `dist/` 权限不对 |
| 刷新子路由 404 | `try_files` 回退路径写错（应带 `/homework/` 前缀） |
| 接口 404 | `proxy_pass` 多了末尾斜杠，前缀被剥掉 |
| 接口 502 | 后端未启动或端口不是 8001，查 `journalctl -u zg-homework-server -f` |
| 页面白屏、资源 404 | Vite `base` 未设为 `/homework/`，或 Router `basename` 缺失 |
